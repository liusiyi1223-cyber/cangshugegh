# 设计文档：互联网总收藏夹

## 1\. 目标与边界

* 目标：让用户把分散在各国内视频平台的收藏，集中整理到一个网站。
* 面向很多用户，但每个用户的数据私有，用户之间不互通。
* 只存链接和元数据，不存视频本身（降低成本，避开版权与平台条款风险）。
* 暂不做：社交、评论、推荐、公开分享。

## 2\. 总体架构

分层如下（自上而下）：

1. 收藏入口：网页上的粘贴框（主入口）；后续加浏览器插件或书签小工具。
2. 后端 API（含账号鉴权）：网页是它的客户端，将来可复用给其他客户端。
3. 服务模块：

   * 收藏服务：收藏的增删改查
   * 标签与搜索：标签、分类、搜索
   * 链接解析：提取链接、还原短链、识别平台、抓取元数据
4. 平台适配器：每个平台一个插件，由链接解析调用。
5. 数据存储：Postgres（用户与收藏）、对象存储（封面缩略图）；搜索 MVP 阶段用数据库模糊匹配，数据量上来后再接专门的搜索引擎。

## 3\. 收藏一条视频的流程

1. 用户在原平台复制分享文本，粘贴到网站输入框。
2. 后端从文本中提取链接（分享文本通常是一段文字夹着一条短链接），并还原短链接。
3. 按链接识别平台，调用对应适配器抓取标题、封面、作者。
4. 将封面转存到对象存储（平台封面常有防盗链，直接引用可能无法显示）。
5. 以 `canonicalUrl` 去重后，保存到当前用户的收藏。
6. 若抓取失败：提示用户手动补标题，补完仍可保存。

## 4\. 数据模型（起步版）

`users`：id、email、密码哈希（或验证码登录所需字段）、createdAt

`favorites`：

* id、user\_id（必填，所有查询按它过滤）
* url、canonicalUrl、platform
* title、cover、author
* tags\[]、note
* status（正常 / 已失效）
* createdAt

建议为 `(user\\\_id, canonicalUrl)` 建唯一约束，防止同一用户重复收藏。

## 5\. 登录

起步用邮箱登录（密码或邮箱验证码）。手机号短信登录、微信扫码登录可后续再加。
数据库层面建议加行级权限作为第二道隔离保险。

## 6\. 抓取原则

* 只取公开元数据，限制请求频率，不绕过登录或风控。
* 不把非官方接口当作核心依赖，平台随时可能改版。
* 先用普通 HTTP 请求加 HTML 解析；个别难抓的页面以后再考虑无头浏览器兜底。
* 记录各平台的抓取失败率，作为是否需要修复适配器的信号。

## 7\. 部署与合规

* 部署在中国大陆云服务器：上线前须完成 ICP 备案，备案成功后 30 日内办理公安联网备案。
* 账号实名类型、备案主体、域名所有者三者须一致。
* 收集用户邮箱，上线前需准备隐私政策。
* 若将来收费，需了解经营性 ICP 许可证要求。
* 具体要求以所选云厂商和所在省管局的最新规定为准。

## 8\. 未决事项

* 首批支持哪几个平台（建议先挑 1-2 个最容易抓取的）。
* 备案主体用个人还是企业。
* 云厂商选择。

## 9\. 决策记录

* 做网站，不做微信小程序（后端 API 独立，以后可加小程序）。
* 部署在中国大陆。
* 只存元数据，不存视频。
* 技术栈：Next.js + TypeScript、Postgres、对象存储。
* 数据库环境：建议选「本地直接装 PostgreSQL」
* &#x20;ORM 选型：Prisma
* &#x20;登录方式：邮箱 + 密码
