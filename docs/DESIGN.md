# 设计文档：互联网总收藏夹

## 1. 目标与边界

* 目标：让用户把分散在各国内视频平台的收藏，集中整理到一个网站。
* 面向很多用户，但每个用户的数据私有，用户之间不互通。
* 只存链接和元数据，不存视频本身（降低成本，避开版权与平台条款风险）。
* 暂不做：社交、评论、推荐、公开分享。

## 2. 总体架构

分层如下（自上而下）：

1. 收藏入口：网页上的粘贴框（主入口）；书签小工具已实现，浏览器插件待做。
2. 后端 API（含账号鉴权）：网页是它的客户端，将来可复用给其他客户端。
3. 服务模块：
   * 收藏服务：收藏的增删改查
   * 标签与搜索：标签、收藏夹、搜索
   * 链接解析：提取链接、还原短链、识别平台、抓取元数据
4. 平台适配器：每个平台一个文件，由链接解析调用。
5. 数据存储：Postgres（用户与收藏、抓取日志）；封面图暂直接引用平台原图，待接入对象存储转存；搜索 MVP 用数据库模糊匹配，数据量上来后再接专门的搜索引擎。

## 3. 收藏一条视频的流程

1. 用户在原平台复制分享文本，粘贴到网站输入框。
2. 后端从文本中提取链接（分享文本通常是一段文字夹着一条短链接），并还原短链接。
3. 按链接识别平台，调用对应适配器抓取标题、封面、作者。
4. 以 `canonicalUrl` 去重后，保存到当前用户的收藏。
5. 若抓取失败：提示用户手动补标题，补完仍可保存。

> 注：设计中的「封面转存到对象存储」尚未实现（见 PLAN 阶段 3），当前直接引用平台原图，存在防盗链失效风险。

## 4. 数据模型（当前实现）

数据库为 Postgres，ORM 为 Prisma。共 4 张表 + 1 个枚举 + 1 张隐式多对多中间表：

### users

| 字段 | 类型 | 说明 |
|---|---|---|
| id | String (cuid) | 主键 |
| email | String | 唯一，登录标识 |
| passwordHash | String | bcrypt 哈希 |
| createdAt | DateTime | |

### favorites（收藏）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | String (cuid) | 主键 |
| userId | String | 外键 → users，所有查询按它过滤 |
| url | String | 原始链接 |
| canonicalUrl | String | 还原后的标准链接，去重依据 |
| platform | String? | 来源平台名 |
| title | String | 标题 |
| cover | String? | 封面图 URL |
| author | String? | 作者 |
| tags | String[] | 标签 |
| note | String? | 备注（预留，暂无 UI 入口） |
| status | FavoriteStatus | ACTIVE / BROKEN |
| createdAt | DateTime | |

约束：`@@unique([userId, canonicalUrl])` 防止同一用户重复收藏；`@@index([userId])`。

### collections（收藏夹）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | String (cuid) | 主键 |
| userId | String | 外键 → users |
| name | String | 收藏夹名 |
| createdAt | DateTime | |

与 favorites 为**多对多**关系（隐式中间表），一个收藏可归多个收藏夹；删除收藏夹不删除收藏本身。`@@index([userId])`。

### fetch_logs（抓取日志，开发者统计用）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | String (cuid) | 主键 |
| platform | String? | 平台名 |
| url | String | 抓取链接 |
| success | Boolean | 是否成功 |
| error | String? | 失败原因 |
| createdAt | DateTime | |

### 枚举

`FavoriteStatus`：`ACTIVE`（正常） / `BROKEN`（已失效）。

## 5. 登录

当前实现：邮箱 + 密码。密码用 bcrypt 哈希存储，登录成功后签发 JWT（jose，HS256），存 httpOnly cookie（有效期 30 天）。所有需要鉴权的接口先取当前用户，收藏查询一律按 userId 过滤，不信任前端传入的用户标识。

手机号短信登录、微信扫码登录可后续再加。数据库行级权限作为第二道隔离保险可后续加。

## 6. 抓取原则

* 只取公开元数据，限制请求频率，不绕过登录或风控。
* 不把非官方接口当作核心依赖，平台随时可能改版。
* 先用普通 HTTP 请求加 HTML 解析；个别难抓的页面以后再考虑无头浏览器兜底。
* 记录各平台的抓取失败率（fetch_logs 表 + /api/stats），作为是否需要修复适配器的信号。

## 7. 部署与合规

* 部署在中国大陆云服务器：上线前须完成 ICP 备案，备案成功后 30 日内办理公安联网备案。
* 账号实名类型、备案主体、域名所有者三者须一致。
* 收集用户邮箱，上线前需准备隐私政策。
* 若将来收费，需了解经营性 ICP 许可证要求。
* 具体要求以所选云厂商和所在省管局的最新规定为准。

## 9. 决策记录

* 做网站，不做微信小程序（后端 API 独立，以后可加小程序）。
* 部署在中国大陆。
* 只存元数据，不存视频。
* 技术栈：Next.js + TypeScript、Postgres、对象存储（待接入）。
* 数据库环境：本地直接装 PostgreSQL。
* ORM：Prisma（当前为 Prisma 7，driver adapter 模式 `@prisma/adapter-pg`）。
* 登录方式：邮箱 + 密码，JWT 存 httpOnly cookie。
* 收藏夹：多对多，一个收藏可归多个收藏夹（文件夹式管理，收藏本身不删）。
* 数据模型：新增 `fetch_logs`（抓取日志）与 `collections`（收藏夹）两张表。
* UI 框架：Tailwind CSS 4。
* 测试框架：vitest。
* 界面风格：卡片网格布局（封面为主）+ 温暖柔和配色（米白底、陶土橙主色）。
